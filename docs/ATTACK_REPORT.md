# BurnProof attack round

One internal round against `contracts/BurnProof.py` and `contracts/BurnGate.py` before deployment. Each finding has at least one test in `test/test_attacks.py` (or `test/test_burnproof.py` where noted). All High and Medium findings were fixed before deployment. Low findings are accepted, and the README "Scope" section describes them.

Severity: **High** means a filer can get TRUE or FALSE for something the page or chain does not support. **Medium** means an honest filing can get a wrong TRUE or FALSE. **Low** means the outcome can only be UNVERIFIABLE or refused, or the behaviour is documented.

| # | Area | Attack | Severity | Status | Fix / reason | Tests |
|---|---|---|---|---|---|---|
| A1 | quote tricks | Split one rendered number with an inline tag (`4<span></span>0%`). Page text read `4 0%`, code took `0%`, and a "0% burned" claim is trivially TRUE | High | Fixed | Inline tags (`span b i a em strong ...`) are removed with no space, as a browser renders them. The page text is `40%`, and a quote `4 0%` is not on the page | `TestQuoteTricks.test_inline_tag_inside_number_reads_as_rendered`, `test_split_number_cannot_be_quoted_as_two` |
| A2 | unicode | Zero-width, bidi-override, soft-hyphen or BOM characters inside a number make code read a different number than a reader sees | High | Fixed | A quote holding any invisible character (an explicit frozen list), a non-ASCII digit, or a non-ASCII percent or per-mille sign ends `UNVERIFIABLE / UNUSUAL_CHARACTERS` | `TestUnicode` (10 tests) |
| A3 | quote tricks | Stitch a quote across two places on the page (`<div>Tokens burned</div><div>40% ...</div>`) | Medium | Fixed | Every non-inline tag ends a block. The quote must lie inside one block | `test_quote_across_blocks_refused`, `_list_items_`, `_br_`, `_table_cells_` |
| A4 | number formats | A range (`40-50%`, `40 to 50%`) was read as its upper bound, which turns an "at least 40%" claim into a stricter 50% one. Malformed groups (`1,2345`, `400.000.000`) were read partially | Medium | Fixed | `AMBIG_RE`: numbers joined by `- – — ~ / to or and`, and digit groups that are not well formed, end `UNVERIFIABLE / AMBIGUOUS_NUMBER` | `TestNumberTricks` (10 tests) |
| A5 | quote tricks / model | Qualified numbers: "Circulating Supply: 92T" taken as SUPPLY_AT_MOST gives a wrong FALSE. Also fee rates ("25% of fees burned"), plans ("will burn 50%"), negations ("not burned"), LP-token burns, and unburned shares | Medium | Fixed | Code guard `QUALIFIERS` (circulat, fee, tax, plan, will, not burn, unburn, liquidity, LP token, per/each/every transaction, ...) ends `UNVERIFIABLE / CLAIM_QUALIFIED` whatever the model says. The prompt also lists these as NONE. "The remaining 50% was burned" (seed S2) is still a claim | `test_circulating_supply_is_not_total` and 8 more |
| A6 | number formats | Claim value 0 ("0% burned") is TRUE for any token | Medium | Fixed | Value must be > 0, else `UNVERIFIABLE / ZERO_CLAIM` | `test_zero_percent`, `test_zero_with_scale` |
| A7 | decimals | A token whose `decimals()` or `totalSupply()` reverts was reported as `RPC_UNAVAILABLE`, which validators accept from a leader without re-reading | Low | Fixed | Reverts are now `TOKEN_UNREADABLE`, which validators must reproduce | `TestTokenTricks.test_decimals_reverts`, `test_total_supply_reverts` |
| A8 | prompt injection | Quote text instructs the model ("answer 4%") | Low | By design | The model sees only the quote, never the page. Code requires the number to be written in the quote and equal to the one code found, and checks the type against `%`. The only freedom left is BURNED_AMOUNT vs SUPPLY_AT_MOST for a non-percent number | `test_prompt_injection_cannot_change_number`, `test_model_never_sees_the_page`, `TestModelOutput` |
| A9 | archive URL | Other hosts, `web.archive.org.evil.io`, userinfo `@`, uppercase host, ports, other archives, `id_` modifiers, bad or future timestamps, fragments, backslashes, percent-encoded hosts, original URL pointing back at archive.org | Low | Refused at the door | Exact prefix `https://web.archive.org/web/`, 14-digit timestamp validated as a real past date, original host restricted to `[a-z0-9.-]` | `TestSnapshotUrl` (35), `TestDoor`, `test_percent_encoded_host` |
| A10 | archive URL | Wayback redirects a non-existent timestamp to the nearest capture, or serves a capture of a redirect to another host | Low | Fixed in design | `Memento-Datetime` must equal the URL timestamp, and `Link rel="original"` must be the filed host, else `SNAPSHOT_MISMATCH` | `TestArchiveTricks`, `TestPage.test_other_capture_served` |
| A11 | archive URL | Lookalike original host (`token.io.evil.io`) | Low | By design | The capture is authentic for that host. The host is stored on every check, and BurnGate only considers the applicant's own site | `test_lookalike_original_host_recorded` |
| A12 | dead addresses | Pass a dead address as the token, or report dead balances above totalSupply | Low | Refused / UNVERIFIABLE | Dead addresses are refused as tokens. `burned > totalSupply` ends `TOKEN_UNREADABLE` | `TestDeadAddressTricks` |
| A13 | dead addresses | A project burns to an address not on the frozen list (e.g. `0x...beef`) | Low | By design | The list is frozen in the contract and published by `get_rules()`. Such tokens read `NO_DEAD_ADDRESS_BURNS` (UNVERIFIABLE), never FALSE | `test_non_dead_burn_address_not_counted` |
| A14 | supply-reducing tokens | Burns that lower `totalSupply` leave no dead-address balance. Percent of the *original* supply cannot be read at one block | Low | By design | No dead-address balance means UNVERIFIABLE for both burn types. A token that mixes both mechanisms is measured by its dead-address holdings only, and the FALSE reason states that measured share | `test_supply_reducing_token_percent_unverifiable`, `test_no_dead_burns_*` |
| A15 | token honesty | A token whose own `balanceOf` lies | Low | Scope | BurnProof reads what the token contract reports at a pinned block, from two RPCs. A dishonest token contract is outside what any chain read can establish | README Scope |
| A16 | proxy tokens | Upgradeable proxy changes logic after the block | Low | By design | Every read names the pinned block. `eth_getCode` must be non-empty at that block | `test_proxy_upgraded_after_block`, `test_every_call_names_the_block` |
| A17 | rebasing / reflection tokens | Balances change without transfers (SafeMoon-style reflections also accrue to dead addresses) | Low | By design | The verdict is at the pinned block. Reflections held by a dead address are as unspendable as burns | `test_rebasing_reads_one_block` |
| A18 | consensus | Leader reports a transport failure (RPC/page down) to force UNVERIFIABLE | Low | Accepted | Validators accept a leader's transport UNVERIFIABLE without reproducing it. This is needed so timeouts always end a filing. It asserts nothing and can be refiled at another block | `test_leader_transport_unverifiable_accepted` |
| A19 | consensus | Leader forges TRUE, chain numbers, claim value, or a QUOTE_NOT_ON_PAGE | Low | Rejected | Validators recompute the page, the number, their own model reading and both RPC reads, and require an identical result | `TestConsensus.test_forged_*` |
| A20 | gate | A griefer archives a false claim on their own page to get a token refused | Low | Fixed in design | BurnGate only considers claims archived from the site the applicant names | `TestGateTricks`, `TestGate.test_false_on_another_site_does_not_refuse` |
| A21 | gate | Mask a FALSE by filing a TRUE (or UNVERIFIABLE) claim later | Low | Fixed in design | "Latest" ranks by snapshot time, not filing order, UNVERIFIABLE is never decisive, and FALSE wins ties | `test_later_filing_of_older_snapshot_cannot_mask`, `test_unverifiable_cannot_mask_false`, `test_false_wins_tie` |
| A22 | rate limit | Many sender addresses (Sybil) | Low | Accepted | Filing is free but every write pays network fees. Duplicates are refused regardless of sender | `test_duplicate_from_other_sender_refused` |
| A23 | page parsing | Unclosed `<script>` or `<` inside text alters the extracted text | Low | Accepted | It can only hide or expose text on the project's own page. The worst case is QUOTE_NOT_ON_PAGE | `test_unclosed_script_hides_rest` |
| A24 | hedges | "over / nearly / almost 40%" | Low | By design | Every number is read as a floor ("at least") with 0.5% tolerance. RULES.md says so | `test_hedge_is_floor` |
| A25 | docs truth | README, RULES and SEEDS state what the code does | Low | Checked | `tools/final_check.mjs` checks addresses, links and seed states against the chain. Rules text was checked line by line against the constants in the contract | `docs/FINAL_CHECK.md` |
| A26 | block choice (1.1.0) | File an old claim at a much later block: dead balances only grow, so a claim that was false when archived can read TRUE years later | Medium | Fixed | The block's time must lie within 24 hours after the snapshot, else `BLOCK_AFTER_WINDOW` (UNVERIFIABLE) | `TestBlockWindow` |
| A27 | claim type (1.1.0) | With code naming the type, a look-alike scale word (`tr\u0456llion`) or a second scale word (`400 thousand million`) would make code read a smaller number than a reader sees | Medium | Fixed | Code names the type only for an all-ASCII-letter quote whose number is not followed by a further scale-like word. Otherwise the model path runs and its answer fails validation | `TestCodeType.test_rules`, `test_cyrillic_lookalike_scale_word` |
| A28 | model influence (1.1.0) | The model withholds or changes the type of a clear claim | Low | Fixed | When the quote's words settle the type, the model is not asked. Every seed is typed by code or stopped by code | `TestSeedQuotesByCode`, `test_model_none_cannot_change_code_typed_verdict` |

High: 2 found, 2 fixed. Medium: 6 found, 6 fixed. Low: 20, all accepted or handled by design as listed above.
